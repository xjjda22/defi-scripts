## [2026-11-03] Venue audit: 40 bad addresses out, 47 verified calls in

**Local only.** Two scripts, `chains.js` corrected.

### The finding

`chains.js` carried addresses that did not exist. A sweep of every 0x address with
`eth_getCode` found **44 dead** and **16 with an invalid EIP-55 checksum** across 9 of the 10
chains that had venues — so quotes on those venues were reverting with no clue why. The worst
offender was `sushiswap.v3.*`, one copy-pasted triple pasted onto six chains where nothing was
deployed.

### Added

- `scripts/venueCheck.js` (`npm run check:venues`) — walks every nested address in
  `chains.js`, checks `eth_getCode` on that chain, and exits 1 on a dead one. No fork needed.
- `scripts/venueDiscover.js` (`npm run chain:discover`) — scans each chain for the canonical
  singleton deployments and **asserts the ABI before believing the address**:
  `feeAmountTickSpacing(3000) == 60` for a Uniswap V3 factory, `allPairsLength() > 0` for a V2
  factory, `feeAmountTickSpacing(10000) == 200` for Pancake V3, `WETH()` for a Balancer V2 Vault.

### Why the ABI check mattered

`eth_getCode` alone was not enough. Eleven chains (linea, celo, ink, bob, soneium, abstract,
megaeth, arbnova, flow, hyperliquid, worldchain) answer with **code at the canonical Uniswap V3
factory address** — but the bytecode there is 2,109 bytes, not the 24,535 of the real factory,
and every ABI call returns `0x`. A code-only check would have shipped 11 fake Uniswap blocks.

### Changed

- `src/config/chains.js` — 51 address lines removed, 37 added. Net venue coverage:
  Uniswap V3 10 chains, Uniswap V2 5, Sushi V2 9 (was 0 usable), Pancake V3 9, Balancer V2 14
  (was 7), Curve 7. **23 of 44 chains now carry at least one venue, and every remaining address
  answers its protocol's ABI.**
- Removed `sushiswap` on optimism/base/metis and `balancer` on 12 chains where the call reverts
  or returns empty — unverifiable is the same as absent, so it is out of the config.

### Known gap

- `worldchain` has a verified Uniswap **V2** factory but no V3; the protocol block was pruned
  with its V3 sibling. Re-add the V2 sub-block when someone touches that chain.

### Security / safety

The playground is the only part of the repo that executes anything on request, so
it is narrow by construction. Verified rather than assumed:

- It binds `127.0.0.1` with no override, unlike `showcase:serve`, which accepts
  `HOST=0.0.0.0` and is safe to expose because it only serves files.
- Any other `Host` header is rejected with **403**, so a DNS-rebound page cannot
  drive Anvil. Confirmed by sending `Host: evil.example.com`.
- The client sends a **feature id, never a command**; the registry supplies both
  the npm script name and the chain. An injection-shaped id returns **400**.
  No client string reaches a shell.
- Runs are **serialised**, matching `forkSuite`, because positions leak between
  tests sharing an Anvil. Confirmed by firing two concurrent runs: they executed
  strictly one after the other.
- `PRIVATE_KEY` is deleted from the child environment; Anvil impersonates a whale.
